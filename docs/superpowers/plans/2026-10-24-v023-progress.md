# v0.2.3 responsive progress and credential prompts

Requested outcome: long operations should visibly remain active, and continuing
should request NAS passwords only for accounts that still need creation.

Implementation choices within the existing wizard:
- Retain honest completed-step percentages, smoothly animate changes, and add a
  persistent activity indicator, translated current operation, elapsed step time,
  and a connection status. Never advance percentages on a timer or report a
  responding web service as proof that an underlying command is making progress.
- Persist step start times and allowlisted activity codes, never command output.
- Derive missing credentials from durable completed user operations; the existing
  OMV ownership checks still run before reusing accounts. Clear/remove the form
  after an accepted resume. Ignore polls started before a mutating UI action.
- Preserve API compatibility with older jobs lacking timestamps or new metadata.

Alternatives: cosmetic smoothing alone leaves long steps unexplained; estimated
percentages would imply measured work. Detailed download-byte streaming is a
larger change and not needed for this fix. Implement actual operation labels and
elapsed time, without an ETA.

Sequence: regressions for partial user completion, resume polling races and long
steps; implement metadata and scoped activity reporting; update bilingual UI;
run Python suite and browser flows, review, then publish a new patch with the
existing state-preserving updater. No repeat disk provisioning or image changes.

Review focus: uncertain user creation still blocks safe replay; no secret enters
progress; accepted resume cannot be overwritten by stale polling; lost connection
stops activity animation; reduced motion/mobile and old saved jobs remain usable.
